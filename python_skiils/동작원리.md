# Python판 동작 원리

## 1. 전체 흐름

```text
사용자가 한국어로 요청
  ↓
Python이 지원 기능과 의도 계약을 질문에 첨부
  ↓ HTTP 요청
로컬 Qwen이 의도 JSON을 회신
  ↓
Python이 JSON의 종류·필드·범위를 검사
  ↓
Python이 위젯·ID·슬라이더 참조·명령을 구성
  ↓
Python 화면에서 사용자가 버튼을 누름
  ↓
현재 슬라이더 값을 읽어 명령 생성
  ↓ HTTP 요청
브릿지 서버 → 제어용 ESP32 → 모터·서보
```

영상은 별도 경로입니다.

```text
카메라용 ESP32 → Python 카메라 수신 → 화면 표시 / CNN 처리
```

영상은 Qwen이나 브릿지 서버에 보내지 않습니다. PC 영상 중계 서버도 만들지 않습니다.

## 2. 처음에는 start_here.py만 따라가기

이 파일은 일곱 단계로 구성했습니다.

1. 사용할 질문과 주소를 변수에 저장합니다.
2. 질문과 카메라 주소를 딕셔너리로 묶습니다.
3. 실제 Qwen에 문의하거나 준비된 회신 예제를 읽습니다.
4. 의도와 구성 결과를 JSON 파일에 저장합니다.
5. 구성요소를 `for` 반복문으로 출력합니다.
6. 모터 슬라이더 값을 27로 바꿉니다.
7. 방향 버튼의 명령을 미리보기로 출력합니다.

기본값 `USE_LOCAL_LLM = False`는 질문을 해석하는 기능을 끈다는 뜻입니다. 이때는 `examples/02_camera_remote.json`을 읽습니다. 이 경로가 LLM의 자연어 해석을 흉내 내는 것은 아닙니다. 준비된 회신을 사용해 그 뒤의 처리 과정을 연습하는 것입니다.

`True`로 바꾸면 `llm.generate()`가 실제 로컬 서버에 문의합니다.

## 3. Python 문법을 읽는 방법

```python
speed = 27
```

`speed`라는 이름에 숫자 27을 저장합니다.

```python
settings = {"cameraUrl": "http://192.168.0.123/stream"}
print(settings["cameraUrl"])
```

딕셔너리는 이름과 값을 짝지어 저장합니다. JSON의 객체가 Python에서는 딕셔너리가 됩니다.

```python
for widget in project["widgets"]:
    print(widget["title"])
```

리스트에 들어 있는 구성요소를 하나씩 꺼내 출력합니다.

```python
if direction == "stop":
    speed = 0
else:
    speed = 27
```

조건에 따라 할 일을 선택합니다.

```python
def make_command(speed):
    return "CMD:motor:" + str(speed)
```

함수는 이름을 붙여 재사용할 수 있게 묶은 처리 과정입니다. 숫자를 문자열과 연결할 때 `str()`을 사용합니다.

코드에는 LLM이 만든 코드를 실행하는 `eval()`이나 `exec()`가 없습니다. 응답은 `json.loads()`로 데이터만 읽습니다.

## 4. 스킬, 의도, 실행 구성은 다릅니다

**스킬**은 프로그램이 실제로 수행할 수 있는 기능입니다.

| 스킬 | 역할 |
|---|---|
| `display_sensor` | 수신 센서 값을 표시 |
| `send_text` | 지정 문자열 그대로 전송 |
| `set_motor` | 모터 속도 명령 |
| `drive_motor` | 방향과 속도가 있는 모터 명령 |
| `set_servo` | 대상과 각도가 있는 서보 명령 |
| `camera_stream` | 영상 표시·시작·종료 |
| `camera_capture` | 학습 샘플 수집 |
| `train_classifier` | 사용자 클래스 학습 |
| `classify_image` | 학습한 클래스 추론 |
| `evaluate_rules` | 클래스 규칙이나 게임 결과 판정 |
| `image_classifier` | 카메라·학습·추론·규칙을 묶은 기능 |

**의도**는 사용자가 원하는 기능과 값입니다. 예를 들어 다음은 정확한 위젯 모양이나 명령 형식을 포함하지 않습니다.

```json
{
  "version": 1,
  "title": "카메라 로봇 조종",
  "features": [
    {"kind": "camera", "input": "configured"},
    {"kind": "motor", "speedControl": "slider", "speed": 50,
     "directions": ["forward", "backward", "left", "right", "stop"]}
  ],
  "unsupported": []
}
```

**실행 구성**은 `compiler.py`가 만든 버튼·슬라이더·카메라 등의 구체적인 데이터입니다. 위 의도는 카메라 1개, 속도 슬라이더 1개, 방향 버튼 4개, 정지 버튼 1개로 바뀝니다. ID와 참조를 Python이 정하므로 LLM이 `speedFrom`을 잘못 작성하는 문제가 생기지 않습니다.

현재 최대 실행 구성요소는 JS판과 같이 8개입니다. 초과하면 일부를 버리는 대신 오류를 표시합니다.

## 5. 로컬 LLM 문의와 회신

`llm.py`의 `generate()`를 읽으면 다음 순서가 보입니다.

1. 모델 이름이 없으면 `GET /v1/models`로 확인합니다.
2. 시스템 안내와 사용자 요청을 `messages` 리스트에 넣습니다.
3. `POST /v1/chat/completions`로 보냅니다.
4. `choices[0]["message"]["content"]`에서 회신을 꺼냅니다.
5. 설명용 `<think>`와 코드 표시를 정리하고 JSON을 읽습니다.
6. 계약을 검사하고 앱을 구성합니다.
7. 잘못된 의도이면 검증 오류를 첨부해 한 번만 수정 요청합니다.

`unsupported`에 미지원 기능이 있으면 즉시 오류를 냅니다. OCR 요청을 다른 센서 앱으로 바꾸지 않습니다. 현재 미지원 범위도 기존 웹앱과 같습니다. OpenCV 알고리즘, 자동 라인트레이싱, 객체 위치·개수 검출, OCR, ViT 등은 구현하지 않았습니다. 카메라 픽셀 읽기·크기 조절을 위해 OpenCV 라이브러리를 쓰는 것과 OpenCV 분석 스킬을 제공하는 것은 다릅니다.

Python판 시스템 안내는 같은 의도 계약과 기능 범위를 사용하되 읽기 쉽게 정리한 문장입니다. 모델의 자연어 해석 결과가 JavaScript판과 매번 동일하다고 보장하지는 않습니다.

## 6. 검증을 하는 이유

`schema.py`는 딕셔너리와 리스트를 차례대로 검사합니다. 숫자·문자열·필수 항목·허용 범위를 확인하고, 선언되지 않은 `widgets`, `id`, `speedFrom` 같은 의도 항목을 거부합니다.

`skills.py`는 장치 프로필에 허용된 스킬인지 검사합니다. 모터 속도는 0–80, 서보 각도는 0–180이고 정지는 항상 0입니다. 문자열 전송은 대소문자와 공백을 유지하고 256자 이하 한 줄로 제한합니다.

계약 검사가 의미 해석까지 보장하지는 않습니다. Qwen이 사용자가 원한 클래스를 빠뜨리는 등의 오류는 여전히 가능하므로 `intent.json`을 확인할 수 있게 저장합니다.

## 7. 버튼을 눌렀을 때

`runtime.py`의 `press_button()`이 처리합니다.

1. 위젯 ID로 버튼을 찾습니다.
2. `skills.resolve_action()`이 현재 슬라이더 값을 읽습니다.
3. Python이 `CMD:motor:forward:27` 같은 문자열을 만듭니다.
4. 미리보기 모드이면 문자열만 반환합니다.
5. 실제 전송 모드이면 브릿지의 `/api/command`에 보냅니다.

정지는 슬라이더 값과 상관없이 `CMD:motor:stop:0`입니다. 여러 명령을 순서대로 보내다가 실패하면 남은 명령은 보내지 않습니다. 전송 응답은 서버의 전송 처리 결과이며 ESP32 출력의 실제 동작 완료 ACK는 아닙니다.

## 8. 영상과 CNN

`camera.py`는 수신 작업을 별도 스레드에서 수행합니다. 화면 작업을 멈추지 않게 하기 위해서입니다. MJPEG에서 JPEG 한 장씩 추출해 최신 한 장만 보관하고, 화면이 느려도 과거 프레임을 계속 쌓지 않습니다. 끊어지면 재연결하고 종료 버튼을 누르면 재연결도 중지합니다.

`cnn.py`의 흐름은 다음과 같습니다.

1. 카메라 프레임 중앙을 정사각형으로 잘라 224×224로 바꿉니다.
2. 고정된 MobileNetV2로 숫자 특징을 추출합니다.
3. 클래스별로 특징을 모읍니다. 최소 5장, 최대 200장입니다.
4. 64개 유닛의 은닉층과 클래스 수만큼의 출력층을 학습합니다. 기본 30회 반복합니다.
5. 새 사진을 추론하고 가장 높은 점수의 클래스와 신뢰도를 얻습니다.
6. 신뢰도와 규칙을 확인하고 필요할 때만 장치 명령을 만듭니다.

분류 결과는 기본적으로 화면에 표시합니다. 물리 장치로 보내는 동작만 `deviceRules`에 넣습니다. `transmit_text`는 화면 문구가 아니라 실제 전송 문자열입니다.

같은 장면에 대한 분류와 자동 주행은 구분해야 합니다. 현재 낮은 신뢰도에서는 새 명령을 만들지 않습니다. 자동 주행용 실패 시 정지·제어 주기·장치 측 시간 초과 처리는 포함하지 않습니다.

## 9. 화면 코드의 특별한 부분

`ui.py`에는 화면을 멈추지 않기 위한 스레드·큐·콜백이 있습니다. 핵심 흐름을 익힌 뒤 마지막에 읽어도 됩니다.

- `partial(함수, 값)`은 버튼을 눌렀을 때 그 함수에 값을 전달하게 합니다.
- `threading.Thread`는 HTTP·학습 같은 오래 걸리는 작업을 분리합니다.
- `queue.Queue`는 작업 결과를 화면 쪽으로 전달합니다.
- `root.after()`는 잠시 뒤 다시 화면 작업을 수행하게 합니다.
- `yield`는 카메라에서 JPEG 한 장씩 꺼내는 반복 함수에서 사용합니다.

Tkinter 화면 수정은 메인 스레드에서만 합니다. 모터 버튼은 클릭 순간의 슬라이더 상태를 복사해 작업 스레드에 전달합니다.

## 10. 저장과 독립 실행

`intent.json`은 LLM이 해석한 내용, `project.json`은 Python이 만든 실행 구성입니다. `llm_trace.json`은 회신 원문과 검증 실패 기록입니다. 학습 후 모델은 `models/feature-N/head.keras`와 `metadata.json`에 저장합니다.

내보내기는 실행 파일·구성·모델을 새 폴더로 복사합니다. 원래 편집기와 LLM 없이 `run_app.py`로 실행할 수 있습니다. Python·Tkinter와 사용하는 기능의 라이브러리는 설치되어 있어야 하며, 처음 MobileNet 기본 가중치를 사용할 때 인터넷이 필요합니다.

현재 Python판과 JS판의 데이터 계약 사본을 함께 관리합니다. 개발용 `tests/compare_javascript.py`는 같은 의도를 두 구현에 넣고 결과 전체를 비교합니다. 일반 실행에는 JavaScript나 Node가 필요하지 않습니다.
