# 가능한 웹앱 개발 사례

PhyVibe의 카메라·영상 분석·하드웨어 제어 기능으로 만들 수 있는 웹앱 사례와 Qwen 입력용 프롬프트를 정리합니다.

이 문서에는 **현재 스킬로 구성할 수 있는 사례**와 **스킬 및 실행 코드 확장 후 가능한 사례**가 함께 포함되어 있습니다. 확장 사례의 프롬프트는 개발 목표이며, 현재 Qwen에 입력하는 것만으로 기능이 구현되지는 않습니다.

## 1. 지원 범위

| 기능 | 현재 상태 | 설명 |
|---|---|---|
| ESP32 카메라 영상 보기 | 지원 | 브라우저가 카메라의 MJPEG 영상을 직접 수신 |
| PC 웹캠 입력 | 지원 | HTTPS 또는 localhost 환경에서 카메라 권한 필요 |
| CNN 이미지 분류 | 지원 | MobileNet V2 특징 추출과 사용자 클래스 2–8개 학습 |
| 샘플 수집·학습·단일/연속 분류 | 지원 | 사용자가 클래스별 샘플을 수집한 뒤 학습 |
| 분류 결과에 따른 모터·서보·텍스트 명령 | 지원 | 장치 프로필이 허용한 스킬과 인자만 사용 |
| 독립 HTML 웹앱 내보내기 | 지원 | 학습 후 내보내면 분류기 가중치도 포함 |
| 자동 라인트레이싱 | 추가 구현 필요 | 선 위치 판단과 반복 주행 제어, 연결 끊김·인식 실패 시 정지 필요 |
| OpenCV 영상 처리 | 추가 구현 필요 | OpenCV.js 실행 환경과 처리별 스킬·위젯 필요 |
| 객체 위치·개수 검출 | 추가 구현 필요 | 객체 검출 모델 또는 조건이 제한된 OpenCV 처리 필요 |
| OCR 문자 인식 | 추가 구현 필요 | OCR 실행 환경, 인식 영역 및 결과 처리 스킬 필요 |

현재 CNN은 영상 전체를 클래스 하나로 분류합니다. 물체의 위치·개수를 출력하거나 글자를 읽는 기능은 포함되어 있지 않습니다. MobileNet 특징 추출기는 고정되어 있고, 사용자 샘플로 그 위의 작은 분류기를 학습합니다.

## 2. 공통 실행 구조

```text
ESP32 카메라 ──직접 영상 수신──→ 웹앱의 브라우저
                                  ├─ 영상 표시
                                  ├─ 영상 분석·CNN 학습 및 추론
                                  └─ 장치 명령 → 브릿지 서버 → 제어용 ESP32 → micro:bit
```

- PC 영상 중계 서버는 사용하지 않습니다. 카메라 모듈과 제어용 ESP32는 별도 장치입니다.
- Qwen은 기능과 의미 있는 값으로 구성된 의도 JSON을 생성하고, JavaScript 의도 컴파일러가 허용된 스킬·위젯·참조를 구성합니다. 실제 영상 분석과 명령 생성은 웹앱의 JavaScript가 수행합니다.
- 카메라·분류만 사용하는 앱에는 하드웨어 브릿지가 필요하지 않습니다. 모터·서보 제어에는 브릿지와 해당 명령을 처리하는 micro:bit 프로그램이 필요합니다.
- 내보낸 웹앱은 PhyVibe와 Qwen 없이 실행할 수 있습니다. 다만 현재 AI 라이브러리와 MobileNet 기본 모델 다운로드에는 인터넷이 필요합니다.
- “이 카메라”는 에디터에 설정한 ESP32 카메라를 뜻합니다. 같은 네트워크에서 접속하고, 내보낸 HTML은 별도의 정적 웹 서버로 제공하여 테스트합니다.
- 현재 펌웨어의 단일 연속 스트림 제약을 고려해 에디터 미리보기와 독립 앱의 카메라 연결을 번갈아 사용합니다.

## 3. 현재 스킬로 가능한 사례

아래 프롬프트는 현재 스킬로 구성할 수 있는 테스트 예시입니다. 생성 설정이 유효해도 실제 인식 품질과 하드웨어 동작은 별도로 확인해야 합니다.

### 3.1 카메라 모니터

**목적:** ESP32 카메라 영상을 표시하고 연결 상태를 확인합니다.

> 에디터에 설정된 ESP32 카메라 영상을 보여주는 웹앱을 만들어 주세요. 카메라 열기와 끄기 버튼을 넣어 주세요. 이미지 분류나 장치 제어는 필요하지 않습니다.

**확인 항목:** 설정한 카메라 주소 사용, 영상 표시, 연결 상태, 연결 종료와 재연결.

### 3.2 물체 유무 분류기

**목적:** 사용자 학습으로 물체가 있는 장면과 없는 장면을 구분합니다.

> 이 카메라와 CNN으로 ‘물체 있음’, ‘물체 없음’을 분류하는 웹앱을 만들어 주세요. 클래스별 샘플 수집, 학습, 단일 분류, 연속 분류 기능을 제공해 주세요. 신뢰도 기준은 80%로 하고 결과만 화면에 표시해 주세요. 장치에는 명령을 보내지 마세요.

**확인 항목:** 클래스별 샘플 수집 → 학습 → 학습에 사용하지 않은 장면으로 분류 확인.

### 3.3 세 종류의 장면 분류기

**목적:** 사용자 정의 클래스 세 개를 구분합니다.

> 이 카메라와 CNN으로 ‘빨간 블록’, ‘파란 블록’, ‘빈 화면’을 구분하는 웹앱을 만들어 주세요. 사용자가 클래스별 이미지를 수집하고 학습하도록 해 주세요. 학습 후 연속 분류로 인식한 클래스와 신뢰도를 표시해 주세요. 장치 제어는 하지 마세요.

**확인 항목:** 클래스 이름 반영, 단일·연속 분류, 낮은 신뢰도 표시. 한 영상에 있는 여러 블록의 위치나 개수를 찾는 앱은 아닙니다.

### 3.4 CNN 결과로 모터 제어

**목적:** 영상 분류 결과를 방향·속도가 있는 모터 명령에 연결합니다.

> 이 카메라와 CNN으로 ‘물체 있음’, ‘물체 없음’을 학습하는 웹앱을 만들어 주세요. 신뢰도 85% 이상일 때 ‘물체 있음’이면 모터를 전진 방향, 속도 30으로 동작시키고 ‘물체 없음’이면 모터를 정지시켜 주세요. 클래스별 샘플 수집, 학습, 연속 분류 기능을 넣어 주세요.

**확인 항목:** `CMD:motor:forward:30`, `CMD:motor:stop:0` 생성 및 micro:bit의 명령 처리.

**현재 한계:** 낮은 신뢰도에서는 새 명령을 보내지 않습니다. 영상 단절·인식 실패 시 자동 정지와 장치 측 명령 시간 초과 처리는 이 사례의 기존 분류 규칙만으로 보장되지 않습니다. 자동 주행에는 별도 보완이 필요합니다.

### 3.5 CNN 분류 결과로 서보 제어

**목적:** 학습한 두 클래스에 서로 다른 서보 각도를 연결합니다.

> 이 카메라와 CNN으로 ‘양품’, ‘불량’을 구분하는 분류 실험용 웹앱을 만들어 주세요. 사용자가 실제 샘플을 모아 학습하도록 해 주세요. 신뢰도 85% 이상이면 ‘양품’은 servo를 30도, ‘불량’은 servo를 150도로 움직여 주세요. 단일 분류와 연속 분류 기능을 넣어 주세요.

**확인 항목:** `CMD:servo:30`, `CMD:servo:150` 생성과 서보 동작. 실제 검사 성능은 별도의 검증 샘플로 평가합니다.

### 3.6 카메라 가위바위보

**목적:** 이미지 분류와 클래스 간 승패 규칙을 조합합니다.

> 이 카메라와 CNN으로 가위바위보 게임을 만들어 주세요. 클래스는 rock, paper, scissors로 하고 사용자가 손 모양 샘플을 모아 학습하도록 해 주세요. PC가 무작위로 선택한 결과와 비교해서 승패와 점수를 표시해 주세요. 사용자가 이기면 micro:bit에 대문자 O, 지면 소문자 x를 보내고 무승부에는 보내지 마세요.

**확인 항목:** 클래스별 학습, 승패 판정, 점수 표시, 명령 대소문자 유지.

### 3.7 카메라를 보며 로봇 수동 조종

**목적:** 영상 표시와 기존 모터 조종 스킬을 한 앱에 배치합니다.

> 이 카메라 영상을 보면서 로봇을 수동 조종하는 웹앱을 만들어 주세요. 전진·후진·좌회전·우회전 버튼을 십자 모양으로 배치하고 별도의 정지 버튼을 넣어 주세요. 모터 속도는 0부터 80까지의 슬라이더 하나로 설정하고 모든 방향 버튼이 현재 슬라이더 값을 사용하도록 해 주세요. 영상은 보기만 하고 이미지 분류는 하지 마세요.

**확인 항목:** 영상과 버튼 표시, 클릭 시점의 속도 반영, 정지 속도 0. 자동 주행 앱은 아닙니다.

### 3.8 PC 웹캠 손 모양 분류

**목적:** ESP32 대신 PC 웹캠을 입력으로 선택합니다.

> ESP32 카메라 대신 PC 웹캠과 CNN을 사용하는 웹앱을 만들어 주세요. ‘손 펼침’, ‘주먹’, ‘손 없음’ 세 클래스를 수집하고 학습하도록 해 주세요. 학습 후 연속 분류 결과를 화면에 표시하고 장치에는 명령을 보내지 마세요.

**확인 항목:** ESP32 주소가 저장되어 있어도 PC 웹캠 선택, 카메라 권한 처리, 학습과 분류.

## 4. 추가 구현 후 가능한 사례

이 절의 사례는 **현재 미지원 기능을 포함한 개발 목표**입니다. 프롬프트만 추가하는 것으로 충분하지 않으며, 스킬 카탈로그·인자 검증·실행 코드·독립 HTML 내보내기를 함께 확장해야 합니다. 아래 스킬 이름은 설계 예시이며 현재 등록된 이름이 아닙니다.

### 4.1 OpenCV 기반 자동 라인트레이싱

**목적:** 바닥의 단일 선 위치를 계산하고 로봇이 선을 따라가도록 합니다.

```text
카메라 프레임 → 화면 아래쪽 관심 영역 → 선 색상/밝기 분리
→ 선 중심 위치 계산 → 화면 중심과의 오차 → 좌회전·전진·우회전
```

**추가 구현:**

- 브라우저 OpenCV.js 로딩과 영상 처리 런타임.
- 관심 영역, 밝은 선/어두운 선 선택, 이진화 기준, 최소 선 크기 설정.
- 중심 오차와 직진 허용 범위, 선 검출 여부 표시.
- 반복 제어, 명령 전송 빈도 제한, 영상 최신성 검사.
- 선 검출 실패·영상 단절 시 정지 및 제어 장치 측 명령 시간 초과 정지.
- 선택적으로 중심 오차에 비례한 조향. 좌우 바퀴 속도를 따로 제어하려면 현재 모터 명령 계약도 확장.

**확장 후 프롬프트 예시:**

> 이 카메라와 OpenCV로 흰 바닥의 검은 선 하나를 따라가는 라인트레이싱 웹앱을 만들어 주세요. 화면 아래쪽 영역에서 선의 중심을 찾고, 선이 왼쪽이면 좌회전, 중앙이면 전진, 오른쪽이면 우회전하게 해 주세요. 속도 조절, 주행 시작과 정지 버튼, 검출 영역과 선 중심 표시를 넣어 주세요. 선을 찾지 못하거나 영상이 끊기면 정지하도록 해 주세요.

**학습 여부:** 모델 학습 없이 처리 기준을 조정합니다.

### 4.2 CNN 기반 자동 라인트레이싱

**목적:** CNN이 선의 상대 위치를 분류하고 그 결과로 주행합니다.

**단계:** 데이터 수집·라벨링 → 학습(트레이닝) → 추론·주행. 학습과 트레이닝은 같은 단계입니다.

| 클래스 | 제어 결과 |
|---|---|
| 선이 왼쪽 | 좌회전 |
| 선이 중앙 | 전진 |
| 선이 오른쪽 | 우회전 |
| 선이 없음 | 정지 |

**추가 구현:**

- 라인트레이싱용 관심 영역을 샘플 수집과 추론에 동일하게 적용.
- 여러 선 위치·곡률·조명에서 데이터를 모으는 학습 화면.
- 추론 주기 조정과 결과 흔들림을 줄이는 판단 유지 조건.
- 낮은 신뢰도·선 없음·오래된 영상·연결 단절 시 정지.
- 별도의 주행 시작/정지 상태와 장치 측 명령 시간 초과 정지.

**확장 후 프롬프트 예시:**

> 이 카메라와 CNN으로 자동 라인트레이싱 웹앱을 만들어 주세요. ‘선이 왼쪽’, ‘선이 중앙’, ‘선이 오른쪽’, ‘선이 없음’ 네 클래스의 샘플을 수집하고 학습하게 해 주세요. 화면 아래쪽 영역으로 학습과 추론을 수행하고, 각각 좌회전·전진·우회전·정지로 연결해 주세요. 주행 시작과 정지 버튼, 속도 설정, 인식 결과를 넣어 주세요. 신뢰도가 낮거나 영상이 끊기면 정지해 주세요.

**현재와의 차이:** 기존 분류·모터 규칙으로 기초 실험은 가능하지만, 자동 라인트레이싱에 필요한 관심 영역과 주행 상태·실패 처리까지 갖춘 기능은 아직 없습니다. 기존 연속 분류는 추론 완료 후 약 500ms를 기다리므로 주행 조건에 맞는 조정과 실측이 필요합니다.

### 4.3 OpenCV 색상 물체 위치 추적

**목적:** 배경과 구분되는 색상 물체를 찾고 위치를 표시합니다.

**추가 구현:** 색상 범위 설정, 관심 영역, 잡음 제거, 윤곽선 검출, 중심 좌표·경계 상자 표시. 예시 스킬: `color_object_tracker`.

**확장 후 프롬프트 예시:**

> 이 카메라와 OpenCV로 파란 공을 찾는 웹앱을 만들어 주세요. 파란색 범위를 조절할 수 있게 하고, 검출한 공의 경계 상자와 중심 좌표를 표시해 주세요. 공이 화면의 왼쪽·중앙·오른쪽 중 어디에 있는지 표시하고, 찾지 못하면 ‘미검출’이라고 표시해 주세요. 로봇은 움직이지 마세요.

**한계:** 색상이 비슷한 배경, 그림자, 물체 겹침에 대한 처리가 필요합니다. 색상 영역 검출이 물체 종류의 의미를 이해하는 것은 아닙니다.

### 4.4 OpenCV 기반 부품 개수 세기

**목적:** 단순한 배경 위에 서로 떨어진 부품의 개수를 셉니다.

**추가 구현:** 이진화, 잡음 제거, 크기·모양 조건, 윤곽선별 번호 및 개수 표시. 예시 스킬: `contour_counter`.

**확장 후 프롬프트 예시:**

> 이 카메라와 OpenCV로 흰 작업대 위의 검은 부품 개수를 세는 웹앱을 만들어 주세요. 관심 영역을 지정하고 너무 작은 잡음은 제외해 주세요. 부품마다 경계 상자와 번호를 표시하고 전체 개수를 보여 주세요. 이진화 기준과 최소 부품 크기를 조절할 수 있게 해 주세요.

**한계:** 서로 닿거나 겹친 부품은 한 덩어리로 검출될 수 있습니다. 현재 영상에 보이는 개수와 컨베이어를 지나간 누적 개수는 다른 기능이며, 누적 집계에는 추적과 중복 방지가 추가로 필요합니다.

### 4.5 AI 객체 위치·개수 검출

**목적:** 검출 모델이 지원하는 종류의 물체를 찾아 위치와 개수를 표시합니다.

**추가 구현:** 브라우저용 객체 검출 모델과 로딩·추론 런타임, 클래스 필터, 신뢰도 기준, 경계 상자 및 클래스별 집계. 예시 스킬: `object_detector`.

**확장 후 프롬프트 예시:**

> 이 카메라 영상에서 사람과 의자를 검출하는 웹앱을 만들어 주세요. 검출 모델이 지원하는 클래스만 사용하고, 물체별 경계 상자와 신뢰도를 표시해 주세요. 현재 화면에 있는 사람 수와 의자 수를 각각 표시하고, 신뢰도 기준을 조절할 수 있게 해 주세요. 장치 명령은 보내지 마세요.

**한계:** 선택한 모델이 해당 클래스를 지원해야 합니다. 사용자 정의 물체를 추가하려면 기존 이미지 분류 샘플과 별도로 경계 상자 라벨링·검출 모델 학습 또는 적합한 모델 도입이 필요합니다.

### 4.6 OCR 라벨 문자 읽기

**목적:** 영상의 지정 영역에서 인쇄된 글자를 읽습니다.

**추가 구현:** 브라우저 OCR 런타임, 언어 모델, 인식 영역, 이미지 전처리, 실행 주기, 결과·신뢰도 표시. 예시 스킬: `ocr_reader`.

**확장 후 프롬프트 예시:**

> 이 카메라 영상의 제품 라벨을 읽는 OCR 웹앱을 만들어 주세요. 사용자가 인식 영역을 지정하고 ‘문자 읽기’ 버튼을 누르면 영문과 숫자를 인식해 주세요. 인식한 문자열과 처리 상태를 표시하고 다시 읽기 버튼을 넣어 주세요. 장치 제어는 하지 마세요.

**한계:** 320×240 전체 영상에서 작은 글자를 읽는 정확도는 제한될 수 있습니다. 글자가 충분히 크게 보이도록 촬영 거리·초점·조명을 조정하고, 필요하면 카메라 해상도와 전송 설정을 함께 변경해야 합니다. 한글 지원 여부는 도입하는 OCR 엔진과 언어 데이터에 따라 확인해야 합니다.

### 4.7 OCR 결과로 분류 게이트 제어

**목적:** 읽은 코드가 지정된 문자열과 일치하면 서보를 움직입니다.

**추가 구현:** OCR 기능 외에 문자열 정규화·일치 규칙, 중복 실행 방지, 인식 실패 처리, 장치 출력 검증이 필요합니다.

**확장 후 프롬프트 예시:**

> 이 카메라로 제품 라벨의 영문과 숫자를 읽는 웹앱을 만들어 주세요. 인식 결과가 정확히 PASS이면 servo를 30도로, 정확히 FAIL이면 150도로 움직여 주세요. 다른 문자열이나 인식 실패에는 명령을 보내지 마세요. 같은 라벨을 연속으로 읽어도 중복 동작하지 않도록 하고, 읽은 원문과 실제 전송 명령을 표시해 주세요.

## 5. 기능 확장 시 변경할 곳

| 위치 | 역할 |
|---|---|
| `webapp/skills.js` | 스킬 이름·인자·지원 범위와 장치 프로필 정의 |
| `webapp/intent.js` | LLM 의도 스키마·검증·공통 프롬프트, 위젯과 ID 및 참조를 구성하는 컴파일러 |
| `webapp/app.js` | Qwen 호출, 실행 구성·명령 검증, 미리보기와 독립 HTML 내보내기 |
| `webapp/vision.js` | 현재 카메라·CNN 화면과 학습·추론·규칙 실행 |
| `webapp/camera.js` | ESP32 직접 영상 수신, 최신 프레임 유지와 재연결 |
| 추가 영상 처리 모듈 | OpenCV·객체 검출·OCR 등 별도 실행 코드 배치 가능 |
| micro:bit 프로그램 | 방향·속도·서보 명령을 실제 장치 동작에 연결 |

공통 카메라 입력과 명령 출력을 재사용하고, 영상 분석 방식별 실행 모듈을 분리하는 구성을 고려할 수 있습니다. 새로운 기능은 카탈로그에 설명만 추가하지 말고 검증·실행·내보내기를 함께 구현해야 합니다.

## 6. 시나리오별 확인 순서

1. 에디터에서 카메라 주소와 실제 영상 수신을 확인합니다.
2. 해당 사례가 현재 지원 범위인지 확인하고 프롬프트로 앱을 생성합니다.
3. CNN 앱은 클래스별 샘플을 수집하고 학습합니다. OpenCV 처리 앱은 구현 후 처리 기준을 조정합니다.
4. 학습에 쓰지 않은 장면과 미검출·낮은 신뢰도 조건으로 결과를 확인합니다.
5. 장치 제어 앱은 생성된 명령, 브릿지 전달, micro:bit 실제 동작을 확인합니다.
6. 학습이 완료된 상태에서 HTML을 내보냅니다. PhyVibe와 Qwen을 종료한 뒤 별도 정적 웹 서버에서 실행합니다.
7. 영상 단절·재연결·제어 중지와 필요한 모델·라이브러리 다운로드 조건을 확인합니다.

현재 지원 사례의 브라우저·생성 검증 코드는 `camera/tests/`에 있습니다. 이 테스트가 아직 구현하지 않은 OpenCV·자동 라인트레이싱·객체 검출·OCR의 동작까지 보증하지는 않습니다.
