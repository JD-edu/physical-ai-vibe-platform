# 의도 기반 웹앱 생성 구조

## 목적

LLM이 사용자 의도와 실행 위젯 형식을 동시에 작성하면서 발생했던 카메라 액션 누락, 잘못된 슬라이더 참조, 장치 명령 형식 오류를 분리합니다. 사용자 질문마다 JavaScript 정규식이나 출력 보정 조건을 추가하지 않는 것이 목표입니다.

```text
사용자 요청
  → Qwen: 의미 있는 기능·값을 의도 JSON으로 추출
  → intent.js: 계약 검증, 허용 기능 확인, 위젯·ID·참조 구성
  → app.js / vision.js: 실행 구성 검증, 명령 문자열 생성
  → 에디터 미리보기 또는 독립 HTML
```

## 역할과 파일

| 파일 | 책임 |
|---|---|
| `webapp/intent.js` | `APP_INTENT_SCHEMA`, 공통 모델 안내, 의도 검증, 입력 선택, 컴파일러 |
| `webapp/skills.js` | 실행 스킬 카탈로그, 장치 프로필과 허용 범위, 공통 명령 전송 |
| `webapp/app.js` | LLM 요청·일반 수정 요청, 실행 구성 검증, 렌더링·내보내기 |
| `webapp/vision.js` | 카메라·CNN UI, 학습·추론과 분류 규칙 검증·실행 |
| `webapp/camera.js` | ESP32 직접 영상 수신, 최신 프레임 유지, 재연결 |

의도 스키마를 모델 안내와 실제 검증에 공통으로 사용합니다. 새로운 의도 종류를 추가하면서 빌더를 구현하지 않으면 오류가 발생합니다. 장치 프로필에서 허용하지 않은 출력은 컴파일 단계에서 거부합니다.

## 의도 예시

카메라를 보며 공통 속도 슬라이더로 로봇을 조종하는 요청:

```json
{
  "version": 1,
  "title": "카메라 로봇 조종",
  "features": [
    { "kind": "camera", "input": "configured" },
    {
      "kind": "motor",
      "speedControl": "slider",
      "speed": 50,
      "directions": ["forward", "backward", "left", "right", "stop"]
    }
  ],
  "unsupported": []
}
```

컴파일러가 카메라 위젯과 모터 슬라이더, 방향·정지 버튼을 만듭니다. LLM은 위젯 ID, `speedFrom`, `action`, `skill`, `CMD:` 문자열을 반환하지 않습니다. 클릭 시 현재 슬라이더 값을 읽고 정지 속도는 항상 0으로 처리합니다.

CNN 결과를 화면에만 표시하는 경우:

```json
{
  "version": 1,
  "title": "양품·불량 분류",
  "features": [
    {
      "kind": "classifier",
      "input": "configured",
      "classes": ["양품", "불량"],
      "confidence": 0.85
    }
  ],
  "unsupported": []
}
```

분류 결과와 신뢰도는 기본 UI가 표시합니다. 장치 전송이 필요할 때만 `deviceRules`를 지정합니다. 효과 종류는 `transmit_text`, `motor_speed`, `drive`, `servo_angle`이며 값은 검증된 고정값입니다. `transmit_text`는 화면 표시가 아니라 물리 장치로 보내는 문자열입니다.

카메라 위젯에는 이미 스트리밍 시작·종료 버튼이 있습니다. 분류 위젯에는 영상 표시·샘플 수집·학습·단일 및 연속 추론이 있습니다. 같은 입력에 단순 미리보기와 분류가 함께 요청되면 분류 위젯의 미리보기를 재사용합니다. 일반적인 모터 조종 버튼은 `motor` 의도로 구성하고, 사용자가 명시적으로 요청한 문자 전송이나 순차 명령 묶음만 `macro`로 구성합니다.

## 검증과 실패 처리

- 정의되지 않은 필드와 기능 종류, 잘못된 값·범위·클래스 규칙은 거부합니다.
- 카메라 주소는 에디터 설정 또는 사용자가 명시한 URL에서 선택합니다. 모델이 지어낸 주소는 거부합니다.
- 미지원 요청은 `unsupported`로 표시하고 다른 기능으로 대체하지 않습니다.
- 잘못된 의도는 공통 오류 메시지로 한 번 수정 요청합니다. 재실패하면 생성 오류를 표시합니다.
- 실행 위젯은 최대 8개입니다. 초과 시 기능을 조용히 버리지 않습니다.
- 자연어 의미 해석 자체는 LLM의 역할입니다. 유효한 의도가 사용자 요구와 완전히 일치한다는 보장은 없으며, 의미 오류를 감지하는 시나리오 검사는 여전히 필요합니다.
- 데모 모드의 로컬 예제 선택은 LLM 경로와 별개입니다. 선택한 예제는 같은 컴파일러를 사용합니다.

## 유지보수 원칙

1. 같은 기능의 표현 차이는 LLM의 의도 해석 문제로 다룹니다. 문장별 정규식과 위젯 보정 코드를 늘리지 않습니다.
2. 지원 기능을 확장할 때 의도 스키마·빌더·실행 스킬·독립 내보내기를 함께 변경합니다.
3. 참조 ID와 장치 명령 형식은 JavaScript가 책임집니다. 모델 출력으로 되돌리지 않습니다.
4. 화면에 표시하는 결과와 물리 장치로 전송하는 효과를 구분합니다.
5. 동작이 같은 기능 조합은 컴파일러 계약 검사로 확인하고, 실제 모델 검사는 대표적인 의도 해석 사례로 확인합니다.

## 검증 명령

```bash
npm test
npm run test:intent:qwen
npm run test:vision:browser
REAL_CNN=1 node camera/tests/browser.cjs
```

- 기본 검사는 의도 스키마, 기능 조합, 장치 권한, 명령 값·참조, 카메라 최신 프레임 처리와 재연결을 확인합니다.
- Qwen 검사는 실행 중인 로컬 서버가 필요합니다.
- 브라우저 검사는 Chrome과 테스트용 가짜 카메라·브릿지를 사용합니다. 실제 하드웨어에 명령을 보내지 않습니다.
- 실제 CNN 검사는 라이브러리·기본 모델 다운로드에 인터넷이 필요합니다. 학습한 가중치의 HTML 저장·새 페이지 복원과 재학습 없는 예측도 확인합니다.
- 내보낸 HTML에는 완성된 실행 구성과 런타임이 포함됩니다. Qwen·에디터·의도 컴파일러는 실행에 필요하지 않습니다.
